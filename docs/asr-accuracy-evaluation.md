# ASR精度・反映時間の評価（2026-09-17）

## 評価範囲

[ReazonSpeechの公開サンプル](https://research.reazon.jp/projects/ReazonSpeech/howto.html)の日本語ニュース音声（speech-001、13.433秒）を使用。16 kHz、mono、PCM16へ変換し、手動確認した正解文と比較した。音声はリポジトリに含めない。

冒頭無音を0／1／2秒とし、各方式を2回実行（5方式×3条件×2回）。これは同じ話者・同じ内容の区切り位置の変化であり、独立した30件の会議音声ではない。専門用語、複数話者、英語、雑音下の一般的な優劣はこの結果から断定できない。

CERはNFKC・小文字化・空白／句読点除去後の文字編集距離。漢字と仮名の表記差も誤りとして数える。置換・脱落・挿入を別々に記録する。挿入は重複以外の余分な語も含む。

## API比較

|方式|実行数|平均CER|API処理時間中央値|
|---|---:|---:|---:|
|qwen-rt-5|6|15.62%|0.839秒|
|qwen-rt-10|6|66.67%|0.810秒|
|qwen-rt-15|6|93.75%|0.811秒|
|qwen-hq|6|0.00%|0.584秒|
|whisper-hq|6|4.69%|0.722秒|

この比較は保存済み音声を待たずに逐次送るAPI試験であり、実時間のマイク送信や画面表示の遅延を測ったものではない。15秒の速報は診断用であり、アプリの設定範囲を拡張していない。初回のモデル待ち時間も結果に含む。Qwenの長い速報窓は余分な語が増えたため採用しない。Whisperの差には「呼び掛け」などの表記差が含まれ、この音声だけでモデル切り替えを決めない。

## 実ブラウザでの変更前後比較

Chromeのマイク入力に同じ日本語WAVを供給し、Podman→LiteLLM→Qwenで録音。音声検出後も32秒録音を継続し、停止前の状態を比較した（各1回）。

|項目|変更前|変更後|
|---|---|---|
|停止前の高精度反映|なし|あり、開始約16.18秒|
|停止前CER|18.75%|0%|
|停止後CER|0%|0%|
|要約・保存・再読み込み|成功|成功|

短い公開音声での結果であり、モデルそのものの精度改善ではない。正しい再認識結果を早く表示できたことを確認した。物理マイクやWindowsの共有音声は未検証。

## 採用した変更

速報の5秒窓と通常の高精度60秒窓は維持する。速報の確定区間末尾で700ms以上の低音量を検出し、前回の高精度確定位置から10秒以上あれば早期再認識する。閾値は既存のenergy gateに合わせており、ニューラルVADではない。既存の速報レコードの境界だけで置き換え、言語脱落を検出する既存の保護処理も維持する。

早期反映後も通常の高精度窓は元の全体境界に揃える。途中の速報レコードをまたぐ置換や、60秒境界での処理停止を防ぐ。録音停止時は残りを処理する。

- `ASR_HIGH_ACCURACY_MIN_SECONDS=10`：早期再認識までの最小蓄積秒数
- `ASR_HIGH_ACCURACY_SILENCE_MS=700`：区間末尾の低音量の継続時間

## 再実行

```bash
.venv/bin/python scripts/eval_asr_live.py   --audio /path/to/16k-mono-pcm16.wav   --reference /path/to/reference.txt   --output artifacts/asr-evaluation.json
```

接続先とキーは環境変数または `.env` の `ASR_BASE_URL`／`ASR_API_KEY` を使う。モデル名は `--qwen-model`／`--whisper-model` で指定できる。報告書にキーは含めない。出力には認識文が含まれるため、会議音声の結果はローカルのartifactsで管理する。
